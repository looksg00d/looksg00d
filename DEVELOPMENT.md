# Developing this profile

The graphics in the README (`assets/*.svg`) are generated by
[`scripts/generate_stats.py`](scripts/generate_stats.py) and refreshed
nightly by [`.github/workflows/refresh-stats.yml`](.github/workflows/refresh-stats.yml).
Nothing here calls a third-party service — everything comes straight from
the GitHub GraphQL API.

## Regenerate locally

```bash
GITHUB_TOKEN=$(gh auth token) GH_LOGIN=<your-username> python scripts/generate_stats.py
```

Requires only the Python standard library — same code path the workflow
runs, so what you see locally is what ships.

## Run the tests

```bash
pip install pytest
python -m pytest scripts/tests -q
```

Covers the pure logic (streak computation, date/number formatting, the
ramp-character mapping) — nothing that hits the network.

## Generate the ASCII portrait

Separate tool, separate from the nightly workflow — a portrait comes from a
photo you pick once and gets committed as a static asset, not regenerated
on a schedule.

```bash
pip install pillow numpy opencv-python-headless rembg onnxruntime
python scripts/generate_portrait.py --input path/to/photo.jpg --login <your-username>
```

First run downloads a ~176MB background-removal model to `~/.u2net/`
(cached after that). Writes `assets/portrait-light.svg` and
`assets/portrait-dark.svg`; wire them into the README the same way as the
stats graphics (`<picture>` + `prefers-color-scheme`).

Only use a photo you have the rights to publish — the whole point of this
project is that everything in the repo is something you can actually stand
behind being there.

What makes a photo work well (the pipeline draws with shadow, not detail —
about 13 brightness levels total):

- **side light**, roughly 45°, not flat frontal light — a uniformly lit
  face renders as a featureless blob
- **tight crop**, chin to just above the hair — a small face in a big
  frame doesn't leave enough columns to resolve eyes
- **1200px+ source resolution** — thin features like glasses frames get
  averaged away on downscale from smaller photos
- **plain background**, and avoid dark clothing against a dark wall
- **slight angle**, not dead-on — gives the nose and jaw a shadow edge

`--cols` defaults to 90 (the article's sweet spot — below ~88 the face
muddies, well above it the block dominates the page). `--no-bg-removal`
skips rembg if the photo's already on a clean plain background.

## Update the embedded font

The SVGs embed subsets of JetBrains Mono as base64 `woff2` (see
`scripts/svg_kit.py`) because fonts can't be linked externally inside an
`<img>`-loaded SVG — only base64 data URIs work there. If a new graphic
needs a character that isn't in `scripts/build_font_subsets.py`'s
`CHARSET`, add it there and rebuild:

```bash
pip install fonttools brotli
python scripts/build_font_subsets.py
```

This downloads JetBrains Mono into `assets/fonts/_src_*.ttf` (gitignored —
dev cache only) and rewrites `assets/fonts/stats-*.woff2` (committed, ~3.6KB
each). The workflow never needs `fonttools` — it only reads the committed
`.woff2` files.

## Design notes

- **Two GraphQL calls**: one for `contributionsCollection` (pinned to whole
  UTC days — see `contribution_data.py`), one paginated call for public
  repositories and their languages (`privacy: PUBLIC` only, so the
  workflow's token and a personal token always agree).
- **Light/dark pairs**: each graphic renders twice (`*-light.svg`,
  `*-dark.svg`) and the README picks between them with `<picture>` +
  `prefers-color-scheme` — one of the few CSS-adjacent tricks GitHub's
  markdown renderer actually keeps.
- **Streaks are scoped to the trailing 365-day window**, not full account
  history, so they stay internally consistent with the sparkline and the
  year heatmap (all three read the same fetch).
